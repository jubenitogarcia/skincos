Corrija a funcionalidade do botão “Acessar” na interface do módulo WhatsApp, garantindo que ele redirecione corretamente para o dashboard do canal conectado, dentro do ambiente Replit.

⚠️ Problema Atual:
- Ao clicar em “Acessar”, o sistema tenta abrir uma nova aba apontando para `localhost:3001` (ou outra porta associada ao canal).
- No Replit, esse tipo de redirecionamento falha com o erro `ERR_CONNECTION_REFUSED` porque as portas internas (como 3001) **não são diretamente acessíveis** pelo navegador.
- Além disso, quando essa navegação é tentada dentro do próprio Replit (preview pane), a aba aberta permanece em branco.

✅ Objetivo:
Permitir que o botão “Acessar” redirecione corretamente para o dashboard da instância/canal conectado, utilizando rotas acessíveis pelo navegador dentro do ambiente do Replit.

🔧 Ações que devem ser executadas:

1. **Identifique todas as portas associadas aos canais ativos (ex: Canal 1 → 3001, Canal 2 → 3002, etc.) no backend.**
   - Cada canal conectado deve estar com sua instância corretamente inicializada e servindo o dashboard de forma independente.

2. **Evite redirecionamentos diretos para `localhost:<porta>` — isso não funciona no Replit.**
   - Essa abordagem precisa ser substituída por um acesso via **rota pública no mesmo domínio do projeto Replit.**

3. **Implemente um mecanismo de roteamento reverso (proxy) no servidor principal (geralmente na porta 3000):**
   - Para cada canal, crie uma rota acessível publicamente (ex: `/canal1`, `/canal2`...), que redirecione internamente para a instância correta (ex: 3001, 3002...).
   - Isso permitirá que o dashboard do canal seja acessado por URLs do tipo:
     ```
     https://<seu-projeto>.<seu-usuario>.repl.co/canal1
     ```

4. **Atualize o comportamento do botão “Acessar” no frontend:**
   - Em vez de construir URLs baseadas em `localhost:<porta>`, o botão deve redirecionar para a nova rota pública proxy (ex: `/canal1`).
   - Esse redirecionamento precisa funcionar tanto na visualização dentro do Replit quanto em nova aba.

5. **Valide se a instância do canal está realmente ativa antes de permitir o redirecionamento.**
   - Se o canal estiver desconectado ou sua instância não estiver rodando, o botão deve ser desativado ou exibir mensagem de erro clara ao usuário.
   - Isso evita a experiência frustrante de ser enviado para uma página em branco ou com erro de conexão.

6. **Garanta compatibilidade com o preview interno do Replit:**
   - O redirecionamento deve abrir corretamente dentro da aba de visualização do Replit.
   - Caso utilize abertura em nova aba, o link precisa apontar para uma URL pública do projeto (rota relativa ao domínio do Replit).

7. **Mantenha toda a lógica de exibição do botão “Acessar” condicional ao status de conexão do canal.**
   - Ou seja, o botão só deve estar visível e ativo se o canal estiver de fato “conectado” e com instância online.
   - Evite redirecionamentos “cegos” para instâncias que não estejam prontas.

8. **Verifique também se as rotas dos dashboards (ex: `/dashboard`, `/crm`) estão corretas internamente dentro de cada canal.**
   - Caso necessário, ajuste o redirecionamento final para `/canal1/dashboard` ou similar, se essa for a rota exata do painel.

🔁 Fluxo ideal esperado após a correção:
- O usuário clica em “Acessar” no canal conectado.
- É redirecionado corretamente para a rota pública mapeada (ex: `/canal1`), que internamente redireciona para a instância do canal.
- O dashboard do canal é carregado corretamente no navegador, seja na aba de preview do Replit ou em uma nova aba.

📌 Após a implementação:
- Verifique se todos os canais redirecionam corretamente para seus dashboards.
- Confirme se o botão “Acessar” só aparece quando o canal está realmente online.
- Me avise quando o comportamento estiver funcionando conforme descrito, para validação e continuidade do fluxo de navegação.
