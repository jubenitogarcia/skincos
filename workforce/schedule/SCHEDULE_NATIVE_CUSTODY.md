# Schedule native capability custody

This is a source proposal for the three internally generated Schedule capabilities. It neither installs nor runs a privileged helper. Existing Actor and global-coordinator custody are outside this helper's paths and inputs.

The enrollment lane is scripts/bootstrap-schedule-public-read-custody.ps1. It is a documented WSL_BOUNDARY_EXCEPTION for fixed Windows VM custody infrastructure, following the authorized fixed Ubuntu/operator bootstrap. It does not extend the ordinary gateway with a root-user option or run project builds/auth as root. Project operator, repository and toolchain preflights still use scripts/invoke-skincos-wsl.ps1 as the actual native admin. The real Windows VM owner's ability to start the fixed root process is an operational prerequisite, not a caller-supplied identity.

The launcher accepts only ProjectRoot, ApprovedSourceSha and Apply. By default it verifies public source and returns a plan, without starting WSL. Before an Apply it requires the canonical SKINCOS origin, approved SHA equal to HEAD and origin/main, main or detached-main, an entirely clean checkout, and matching source tree. It captures the four fixed public source files, including the unchanged gateway, from exact Git blobs and checks the Windows files after strict UTF-8 and CRLF-to-LF normalization. It never dot-sources checkout code; its small Windows argv renderer is local, and gateway execution is reached only after source approval. The gateway is compiled into an in-memory ScriptBlock from its captured Git bytes and invoked in child scope with the original ProjectRoot; its mutable checkout path is never reopened for execution. The reviewed gateway resolves repo/worktree paths from ProjectRoot/RepoRoot, has no PSScriptRoot dependency or source import, and also has a literal SHA256 pin so future gateway changes require explicit review. Reparse paths, BOM, NUL, lone CR and oversized sources fail closed. Both the helper and receiver have reviewed literal SHA256 pins. The actual publisher's source/main/manifest/lease gates remain unchanged.

After the unchanged admin gateway's full preflights, the launcher rechecks source/main/tree. It sends only immutable public source snapshots and source IDs to the fixed Ubuntu-24.04 root /usr/bin/python3 interpreter with -I and -B, no shell command string. The fixed interpreter program independently validates the receiver pin; the receiver validates a bounded strict four-field JSON contract, exact source IDs, canonical base64 and the helper's own literal pin. The helper is compiled and run from those verified immutable bytes, never reopened from mutable checkout or stdin. Its only operation is the literal provision. No installed helper, sudoers rule, group, membership, service, Actions runner bridge or general root command permission is created. No environment or secret input is accepted; the Windows root process forwards only the fixed Windows lifecycle environment allowlist, without WSLENV or loader/Python/auth injection.

Do not grant broad sudo or reuse the legacy admin group106. The existing native operator admin must have primary group skincos-operator-admin; that exact group must differ from the legacy admin group and from root.

The command accepts only the literal operation provision. It accepts no target, secret, UID/GID, environment override or stdin contract. Its isolated system-Python shebang ignores user Python path injection. The target is fixed:

    /etc/skincos/schedule-public-read/native-capabilities.json

The final directory must be root-owned0750 with only the dedicated operator group. The final regular file is root-owned0640 with that same group and one hard link. Root-owned ancestors must be non-writable by group/others, free of symlinks, extended/default ACLs, and traversable without a grant to the legacy group. Missing fixed directories may be created privately; existing ownership, groups, modes or ACLs are never repaired or broadened. Unknown ACL inspection fails closed. An incompatible ancestor is an owner prerequisite, not permission to chmod/chown another product's path.

Every existing target, including a dangling symlink, is refused before key generation and without reading content. After real Linux root identity, fixed-path/group/absence checks, the generator sets only its own process's core limit0, dumpable0, and memory locking current+future+on-fault. It creates three distinct32-byte CSPRNG values encoded as64 lowercase hexadecimal digits: SCHEDULE_PUBLIC_READ_CORE_HMAC_KEY, SCHEDULE_PUBLIC_READ_EDGE_HMAC_KEY and SCHEDULE_PUBLIC_READ_PROBE_HMAC_KEY. No existing key is accessed or rotated. Publisher source/main, custody, version, manifest and remote-lease guards remain unchanged.

Creation uses an exclusive no-follow private file in the verified directory, root/dedicated-group0640 metadata, file fsync, atomic no-replace hard-link publication, directory fsync, removal of the own temporary link and another directory fsync. A concurrent creator cannot be overwritten. The canonical file is never deleted after publication, including an uncertain durability failure. A crash can leave two links; the consumer's existing nlink1 check then fails closed. Do not rerun to rotate or erase it: the owner must inspect metadata and resolve the interrupted transaction before publisher use. Canonical custody and its private transaction file are the only secret disk locations; no plaintext log, stdout value, secret digest or command argument is created. Output contains only fixed path/group and creation/protection metadata. Errors use one public constant.

The focal tests import validation and atomic storage functions only, use deterministic synthetic values in native-admin temporary directories, and never invoke the privileged CLI, /etc creation, memory protector, real key generation, remote access or install. They exercise actual no-replace filesystem behavior, private modes, refusal of existing/symlink targets, concurrent winners, pre/post-publication fsync failure, ACL refusal and payload wiping. Fixture UID adaptation is confined to the storage unit boundary; the real entrypoint always requires UID0 and the fixed canonical path.

Run the synthetic focal serially through the typed project gateway as the actual native admin; no skip flags or elevated helper execution:

    scripts/invoke-skincos-wsl.ps1 -ProjectRoot <dedicated-worktree> -WslExecutable C:\Windows\System32\wsl.exe -Executable /usr/bin/python3 -Argument @('-B','-m','unittest','-v','scripts.tests.test_schedule_public_read_custody','scripts.tests.test_schedule_public_read_enrollment')

The pure Windows infrastructure focal scripts/tests/schedule-public-read-enrollment.test.ps1 loads only the dot-source renderer/validators, never WSL. It checks exact root argv, immutable captures, tampered source/receiver rejection, main/origin/clean gates, UTF-8/EOL refusal and absence of generic command/user/environment/skip parameters. A synthetic source snapshot test replaces the gateway file after capture and invokes the captured gateway with a guaranteed absent WSL executable; only the approved code reaches its expected unavailable-executable rejection, and the replacement bytes never execute. Receiver tests run as actual nonroot native admin and use only reviewed public code/synthetic JSON; the real euid prevents reaching stdin, compilation, generation or /etc. No test simulates successful privileged enrollment.

After review and merge, the owner can verify the plan using the real merged clean-main SHA:

    scripts/bootstrap-schedule-public-read-custody.ps1 -ProjectRoot <clean-main-checkout> -ApprovedSourceSha <real-merged-main-SHA>

Only the authorized owner may add Apply for the one initial creation. Never substitute an invented SHA, bootstrap permission or identity. A process failure, timeout, output mismatch or uncertain durability is a fail-closed result and is not retried automatically; observe target metadata before any subsequent step. An existing target is always refused, including on reentry. The launcher emits reconstructed public metadata only and never forwards raw child stdout/stderr.

Passing the synthetic tests is source evidence, not proof of root privilege, current group topology, actual protected generation/custody, supported Windows argv/environment transport or a remote lease. Actual enrollment, private metadata readback and publisher access remain prerequisites. This source-only checkpoint may be committed locally for recovery; no Apply, installation, real generation, push or deployment is part of it.
